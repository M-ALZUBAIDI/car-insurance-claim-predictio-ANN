# Car Insurance Claim Risk Prediction

An end-to-end deep learning pipeline that predicts whether a policyholder is likely to file an insurance claim, using demographic, financial, and driving-history data. Built as the final project for the Deep Learning Unit.

**Team:** Turki, Mohammed, Abdulaziz, Nawaf, Saleh

---

## Problem

Insurers need a fast, consistent way to flag high-risk applicants before a policy is issued. This project builds an Artificial Neural Network that takes raw applicant data and returns a claim-risk probability, trained and evaluated with a specific business priority in mind: **missing a real claim is costlier than a false alarm**, so the model is optimized for recall on the claim class rather than raw accuracy.

## Dataset

- **Source:** `Car_Insurance_Claim.csv` — 10,000 applicant records, 19 raw columns
- **Target:** `OUTCOME` — 1 if the policyholder filed a claim, 0 otherwise
- **Class balance:** 68.7% no claim / 31.3% claim (moderately imbalanced)
- **Missing values:** Credit Score (982 missing), Annual Mileage (957 missing) — median-imputed

## Pipeline

| Stage | What happens |
|---|---|
| 1. Preprocessing | Drop `ID`/`POSTAL_CODE` → median-impute → ordinal-encode ordered features (Age, Driving Experience, Education, Income, Vehicle Year) → one-hot encode nominal features (Gender, Race, Vehicle Type) → stratified 80/20 split → `StandardScaler` (fit on train only) |
| 2. Model design | 5 ANN variants, each adding one technique on top of the last |
| 3. Training & tuning | L2, Dropout, EarlyStopping, ReduceLROnPlateau, BatchNorm, class weighting, plus a Keras Tuner `RandomSearch` (15 trials) |
| 4. Evaluation | Accuracy, precision, recall, F1 (class 1), confusion matrix — computed consistently across all 5 models |
| 5. Deployment | Saved model + scaler/encoder artifacts, wrapped in a reusable inference function |

## Model Comparison

| Model | Accuracy | Precision (claim) | Recall (claim) | F1 (claim) |
|---|---|---|---|---|
| 1 — Baseline ANN | 0.824 | 0.736 | 0.681 | 0.708 |
| 2 — + L2 + Dropout | 0.830 | 0.737 | 0.711 | 0.724 |
| 3 — + ReduceLROnPlateau | **0.831** | 0.728 | 0.735 | **0.732** |
| 4 — + BatchNorm | 0.825 | 0.727 | 0.707 | 0.717 |
| **5 — + Class Weighting** | 0.808 | 0.652 | **0.829** | 0.730 |
| Keras Tuner (best trial) | 0.820 | — | — | — |

**Final model: Model 5.** It trades ~2.3 points of accuracy for a 14.8-point recall gain on the claim class (68.1% → 82.9%) — the right trade-off given that a missed claim is more costly to the business than a false positive. Full rationale and the accuracy/F1 alternative (Model 3) are documented in the notebook and project slides.

A post-hoc decision-threshold sweep (0.5 → 0.595) was also tested: it recovers accuracy to 82.45% at F1 = 0.740, but was **not** adopted for deployment since it trades away some of the recall gain that motivated picking Model 5 in the first place. The default 0.5 threshold is used in the shipped model.

## Known Limitations

- **Accuracy ceiling ~83–85%** — the available demographic/behavioral features carry limited separating signal for this problem; this is consistent with public results on this dataset.
- **Keras Tuner overfits to a single validation split** — the best trial reported 84.6% val accuracy but only 82.0% on the held-out test set, a known weakness of `RandomSearch` without cross-validation.
- **Precision–recall trade-off is real, not a bug** — Model 5's higher recall comes with more false positives; this was a deliberate choice, documented above.
- **No external signal** — telematics, claims history, or inspection data could likely push performance further.

## Running the Project

1. **Train / reproduce:** open `notebooks/insurance_risk_ann.ipynb` in Google Colab or Jupyter and run all cells top to bottom. This regenerates the artifacts in `models/`.
2. **Run inference standalone:**

   ```bash
   pip install -r requirements.txt
   python src/inference.py
   ```

   Edit the `sample_applicant` dict at the bottom of `src/inference.py` to score a different profile.
